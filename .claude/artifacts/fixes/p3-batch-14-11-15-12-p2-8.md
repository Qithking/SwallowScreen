## 逐项记录

### #14 UpdateChecker cancel 后仍以 .failure 回调
- **Symptom**: 调用方（AppPopoverView / SettingsView.AboutView）弹出更新面板后关闭/重开时，旧 check 被 cancel，completion 仍以 `.failure(.network(NSURLErrorCancelled))` 交付，UI 误显示「检查失败」
- **Root cause**: L57 注释称「不会调用其 completion」与实际不符——`task?.cancel()` 后 URLSession 会以 `NSURLErrorCancelled (-999)` 回调 completion，error 分支未过滤该码
- **Fix**（UpdateChecker.swift）:
  1. check 内 error 分支开头增加 cancelled 过滤：`(error as? URLError)?.code == .cancelled || (error as NSError).code == NSURLErrorCancelled` → 静默 return（不交付任何结果）
  2. 修正 cancel() 注释为实际语义（completion 会以 NSURLErrorCancelled 回调，check 内部已静默过滤）
- **Verification**: 静态审查（cancel / 新 check 抢占两条取消路径均覆盖）+ xcodebuild 构建通过

### #11 AppDelegate setCurrentAppScreen try? fetch 吞错 → 重复记录
- **Symptom**: SwiftData Store 异常（如迁移/IO 错误）时 `try? fetch` 返回 nil，代码误走 insert 分支，同 bundleID 产生重复 AppInfo 记录
- **Root cause**: fetch 失败（异常）与「记录不存在」被 try? 合并为同一路径
- **Fix**（AppDelegate.swift）: fetch 改 do-catch——失败时 os_log 记录错误 + return，跳过本次保存与 moveAppToScreen；仅 fetch 成功且确实无记录时才 insert。return 语义与 save 失败分支（L507）一致
- **Verification**: 静态审查 + xcodebuild 构建通过

### #15 keyCodeToString 每次渲染重建字典
- **Symptom**: 快捷键录制视图每次渲染调用 keyCodeToString（L688），函数体内重建 70+ 条目字典
- **Root cause**: 常量键码表误置于函数体内
- **Fix**（SettingsView.swift）: keyMap 提为 `private static let keyCodeNames`；函数体缩为 `Self.keyCodeNames[keyCode] ?? "Key(\(keyCode))"`（struct 内 static 可行）
- **Verification**: 静态审查（键值内容零改动，仅提级）+ xcodebuild 构建通过

### #12 loadIconSync 对 .app 目录死分支
- **Symptom**: CGImageSource→CGContext 解码路径对 .app bundle 目录必然失败（ImageIO 无法解码目录），25 行代码从未生效，实际始终走 L210 NSWorkspace 兜底
- **Root cause**: 优化实现假设 path 为图标文件，而调用方（Task.detached）传入的均为 .app 目录路径
- **Fix**（AppManager.swift）: 删除死分支，函数体缩为直接 `return NSWorkspace.shared.icon(forFile: path)`，注释说明死分支成因
- **Verification**: 静态审查（全库唯一调用点 L132-135 传 .app 路径）+ xcodebuild 构建通过
- **备注**: NSWorkspace 返回多尺寸 representation 的内存开销维持现状——上一轮 M3 优化目标（24×24 单表示）对 .app 目录不可达，若需进一步压缩需走 icon(forFile:) 后手动缩放，属新优化项不在本批范围
